# memo-snapshot — 快照分析

读取 `.memo/` 中最新的压缩后 active 快照，让用户选择参考源，结合当前项目状态逐条分析，给出"保留/删除/提全局"建议。

## 触发条件

- 用户直接输入 `memo-snapshot`
- 主技能 `memo -s` 分发调用

## 执行流程

### 第一步：读取快照

读取 `.memo/_index.md`，获取最新的压缩后 status=active 的条目。

| 情况 | 行为 |
|------|------|
| 无 active 条目 | 输出提示并结束：`❌ 未找到 active 的快照` |
| 仅 1 条 | 自动选中该条，并读取快照文件内容。 |
| 多条 | 停止该技能执行，告知用户“该技能仅适合压缩后的快照分析，请先执行 memo-index 或 memo -i 技能压缩快照。” |

### 第二步：选择参考源

向用户展示参考源选项（可多选）：

```
📋 请选择项目状态参考源（可多选）:

  [1] 读取 docs/ 目录下文件内容
      扫描 docs/ 下的目录和文件，读取文件内容

  [2] 读取 MEMO.md
      加载已有全局条目，避免重复提升

  [3] 扫描项目根目录结构
      2 层深度的目录树，了解项目当前形态

  [4] 自定义输入
      用户输入参考源编号，或直接输入自定义需求，按用户要求执行

  [5] 读取整个项目
      开启子代理扫描项目根目录，读取所有文件内容【谨慎使用】

```

### 第三步：收集参考信息

根据用户选择执行对应操作：

- `[1]`：扫描 `docs/`，读取所有 `.md` 文件完整内容
- `[2]`：读取 `MEMO.md`
- `[3]`：运行 `Get-ChildItem -Depth 2 | Select-Object FullName`（排除 `.git/`、`.memo/`、`node_modules/`）
- `[4]`：根据用户输入执行。支持输入编号（如 `1,2,3` 快速组合已有选项），或直接描述当前项目状态由 AI 自行判断
- `[5]`：启动子代理（subagent）扫描项目根目录，读取所有源码文件内容（排除 `.git/`、`.memo/`、`node_modules/`）。**仅建议在项目规模较小时使用，大项目会消耗大量 token**

收集完成后，汇总参考信息供后续分析使用。

### 第四步：逐条分析

将快照的 5 维度条目与参考源进行比对，每条输出建议：

| 建议 | 判定条件 |
|------|----------|
| **保留** | 该条目与当前项目状态一致，仍有效 |
| **删除** | 已过时、已被后续内容覆盖、与实际项目不符、或参考源中已明确解决 |
| **提全局** | 属于长期有效的架构/设计决策，适合沉淀到 MEMO.md |
| **待核实** | 信息不足以判断，需用户人工确认 |

具体维度分析逻辑：

**设计意图**
- 是否在 MEMO.md/docs 中已记录 → 提全局或删除
- 是否与当前目录结构/代码风格一致 → 保留
- 是否已被后续快照中的新设计取代 → 删除

**已否决方案**
- MEMO.md 是否已有记录 → 提全局或删除
- 方案对应的技术是否仍在项目中出现 → 保留提醒
- 否决理由是否仍成立 → 保留；否则建议删除

**已知坑位**
- docs 中是否有对应的排查文档/指南 → 提全局或删除
- 坑位是否已被修复（从快照自身或参考源判断）→ 删除
- 是否仍可能复现 → 保留

**当前断点**
- 项目现状态是否已推进过该断点 → 删除
- 断点内容是否已转化为新功能 → 删除
- 是否仍停滞 → 保留

**方向约束**
- MEMO.md 是否有同类约束 → 提全局或删除
- 约束是否仍适用 → 保留
- 是否已被项目实际走向推翻 → 删除

### 第五步：输出建议单

```
📋 快照分析建议 — <文件名>（参考源：[1/2/3/4/5]）

| # | 维度 | 条目摘要 | 建议 | 理由 |
|---|------|---------|------|------|
| 1 | 设计意图 | 使用 X 而非 Y | 保留 | 参考源显示项目当前仍使用 X |
| 2 | 已否决方案 | 方案 Z | 删除 | 参考源中已无相关痕迹，不再适用 |
| 3 | 已知坑位 | 缓存失效 | 提全局 | 属于长期架构坑位，建议写入 MEMO.md |
| 4 | 当前断点 | 用户系统待测试 | 待核实 | 参考源中未找到相关完成记录 |

共 X 条 | 保留 Y 条 | 删除 Z 条 | 提全局 W 条 | 待核实 V 条

ℹ️ 以上为 AI 建议，请结合项目实际进行审核，给我最终反馈后执行修改动作。
```

### 第六步：根据反馈执行修改

等待用户审核后的反馈，用户可指定每条条目的最终处理方式：

```
📋 请给出最终处理指令。例如：
  - "条目1、3删除"
  - "条目5提到全局"
  - "条目2保留"
  - "按建议全部执行"
  - "条目1删除，条目3保留，条目5提全局"
```

根据用户的指令执行对应操作：

| 指令 | 操作 |
|------|------|
| **删除** | 从快照文件中移除该条目内容 |
| **保留** | 不做任何修改 |
| **提全局** | 从快照中移除，追加到 `MEMO.md` 对应维度区块（做语义去重，避免重复写入） |

所有修改直接替换原快照文件内容，不新建快照文件。

执行完成后输出摘要：

```
✅ 修改完成

操作摘要：
- 删除：X 条
- 提全局：W 条 → MEMO.md
- 保留：Y 条

快照文件已更新：.memo/<文件名>
```

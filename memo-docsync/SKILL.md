# memo-docsync — 文档同步

从当前对话提炼与 docs/ 文档相关的变更内容，推荐需要更新的文档，经用户确认后同步更新 docs 文件及 MEMO.md 中的文档索引表。

## 触发条件

- 用户直接输入 `memo-docsync`
- 主技能 `memo -d` 分发调用

## 文件规范

### MEMO.md 格式

项目根目录下的 MEMO.md：

```markdown
# MEMO

## 用户规则

<!-- 用户可在此区域写入自定义规则、偏好 -->

---

## 文档索引表

| 编号 | 文件名 | 相对路径 | 简介 | 状态 | 最后同步 |
|------|--------|----------|------|------|----------|
```

- **用户规则**：用户自定义规则区，memo-docsync 不修改此区域
- **文档索引表**：记录 docs/ 下所有文档的元信息

MEMO.md 还可能包含 `## 设计意图`、`## 已否决方案`、`## 已知坑位`、`## 方向约束` 等区块，由 memo-review 写入，memo-docsync 不处理这些区域。

### docs/ 目录

- 项目根目录下的文档目录
- 存放架构、API、数据库设计、需求等文档

## 执行流程

### 第一步：分析对话

扫描当前对话，提炼与 docs/ 文档相关的变更内容：

1. 对话中直接提及或讨论了哪个文档
2. 代码修改影响了哪个文档描述的功能模块
3. 决策或约束与哪个文档记录的规范相关

**提取规则（防止把假设写成事实）：**

- 只推荐同步**已确认的事实**：已完成的代码变更、已做出的明确决策、已验证的功能
- **不推荐**同步讨论中的假设、备选方案、未验证的想法
- 如果对话中某项变更既讨论了又实现了，只提取最终实现的部分，忽略中间讨论过程
- 判断标准：如果这条信息写进 docs，会不会误导未来的开发者以为"这是已确定的"？会 → 不推荐

### 第二步：检查目录与文件

检查项目根目录：

- 如果 `MEMO.md` 不存在，输出：
  ```
  ⚠️ 未找到 MEMO.md，跳过文档同步
  ```
  并结束流程。
- 如果 `docs/` 目录不存在，输出：
  ```
  ⚠️ 未找到 docs/ 目录，跳过文档同步
  ```
  并结束流程。

### 第三步：扫描 docs 目录

递归扫描 docs/ 目录，获取当前所有文件列表。

与 MEMO.md 中文档索引表对比：

- **新增文件**：加入索引表
- **已删除文件**：从索引表中移除
- **已有文件**：保留原信息

### 第四步：推荐与确认

汇总第一步和第三步的结果。如果第一步未检测到对话中的文档变更，且第三步未发现文件增减，输出以下提示并结束流程：

```
ℹ️ 未检测到需要同步的文档变更
```

否则输出推荐列表：

```
📋 根据本轮对话，建议同步更新以下文档：

| # | 文档 | 原因 |
|---|------|------|
| 1 | api.md | 本次修改了 API 接口定义 |
| 2 | database.md | 新增了表结构 |
```

询问用户确认：

```
是否同步以上文档？可以选择：
- 全部同步
- 选择部分文档（输入编号，逗号分隔）
- 跳过（不同步任何文档）
```

根据用户选择决定后续处理范围。

### 第五步：执行同步

对用户确认需要同步的每个文档：

1. 读取该文档当前内容
2. 根据本轮对话的上下文信息，更新文档中的相关内容
3. 新增文件需补充简介

**更新规则：**

- 根据变更内容定位文档中对应的章节标题，在同一章节内修改，不跨章节挪动内容
- 变更信息如果属于已有章节的范畴，在原章节内追加或修正；如果不属于任何已有章节，在文档末尾新增对应章节
- 保持文档原有的标题层级、段落风格和 markdown 格式
- 不重新排列章节顺序，不修改无关内容

### 第六步：更新索引表

更新 MEMO.md 中文档索引表：

- 同步的文档：状态 → "已同步"，最后同步 → 当前日期
- 新增文档：补充完整信息
- 已删除文档：移除

### 第七步：输出摘要

```
✅ 已同步 [数量] 个文档

同步列表：
- api.md → 已同步（更新 API 定义）
- database.md → 已同步（新增表结构）

文档索引表已更新
```
